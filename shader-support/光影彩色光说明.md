# mzycBuild · 光影包「彩色光照」使用说明

> 目的：让**红色灯光方块在支持彩色光照的光影包下投出红光**；原版（不装光影）保持正常白光即可。

---

## 一、先说清楚原理（很重要）

**原版 Minecraft 的光照没有颜色概念。** 方块只能决定「发多发亮（0~15 级）」，发出来的光
永远是同一种暖白色 —— 红石灯、萤石、屏幕里的红方块，光色完全一样。所以不管模组怎么写，
**原版环境下都不可能投出红光**。

彩色光照是**光影包**（配合 Iris / OptiFine）自己实现的效果。模组能做、也已经做了的事只有一件：
**让方块有一个稳定、规范的 ID**，光照包才能把它「认出来」并归到某个颜色：

| 方块 | 注册 ID |
|---|---|
| 红色灯光方块 | `mzycbuild:red_light_block` |
| 黄色灯光方块 | `mzycbuild:light_block` |

**剩下的「染成红色」必须在光影包那一侧完成**（把 ID 加进红色光源组）。这就是为什么需要一个
`block.properties` 的改动，而不是改几行模组代码。

> 注：Iris 会把「这个方块是光源」告诉光影包，但**不给颜色**，所以没有配置时 mod 光源一律
> 按白光渲染 —— 这正是你现在看到的情况。

---

## 二、三种做法，按你用的光影包挑一个

### 做法 A：改光影包的 `block.properties`（最通用，推荐）

1. 打开光影包目录：`.minecraft/shaderpacks/<你的光影包>.zip`（解压出来改，或直接改文件夹版）。
2. 找到 `shaders/block.properties`。
3. 找到**已经在投红光的那一组**（里面通常有 `redstone_lamp` / `redstone_torch` / `crimson_*` 之类），
   把 `mzycbuild:red_light_block` 追加到那一行末尾（空格分隔）。
4. 想给黄方块染黄光，就同样把它加到**黄/暖白那一组**（通常有 `glowstone` / `sea_lantern` / `torch`）。
5. 存盘，游戏里按 **F3 + T** 重载光影（或重进一次世界）。

⚠️ 三条硬规矩：
- 一个方块 ID 在整个文件里**只能出现一次**（重复会让光影报错）；
- **不能新建颜色组**，只能追加到已有组；
- 只有支持彩色光照的光影包才有用（Complementary / BSL / Bliss / Photon / Rethinking Voxels…）。

> 现成模板见同目录 `block.properties`。

### 做法 B：用光影包自带的彩色光 GUI

不少整合光影（如 Bliss 的 Floodfill Colored Lighting、部分 Complementary 衍生包）在
**光影设置 → 环境光/彩色光** 里有「按方块调色 / 自定义颜色」的界面，可以直接搜方块 ID 调色，
不需要手动改文件。路径各包不同，一般在「彩色光照 (Colored Lights)」分类下。

### 做法 C：什么都不用做（部分光影包会自动取色）

一些光影包（如 **Rethinking Voxels**、**IterationVX**）会**按方块贴图的颜色自动判定光源颜色**。
本模组的红色灯光方块用的是纯正红的高饱和贴图，这类光影包**开箱即用、会自动投红光**，
不需要任何配置。

## 三、和 `/hdyc` 的关系

闪烁节奏（默认「亮 2 秒 / 灭 2 秒」）由模组的 `/hdyc X` 控制，和光影无关：

```
/hdyc 2.00     # 亮 2 秒、灭 2 秒（默认）
/hdyc 0.50     # 亮 0.5 秒、灭 0.5 秒（快速闪烁）
/hdyc 1.25     # 支持 2 位小数
/hdyc          # 查询当前值（只回数值，如 2.00）
```

光影开彩色光照后，红光会**跟着这个节奏一起闪**（因为闪的是方块本身的亮度等级，
光影只是在它发光时给光染色）。

## 四、常见问题

- **开了彩色光照后，红方块的光还是白的？** → 说明它的 ID 没被归进红色组，回到做法 A。
- **改了 block.properties 没用？** → 检查是不是直接改了 zip 没重载、ID 写错（要用
  `mzycbuild:red_light_block`，带命名空间）、或这个包根本不支持彩色光。
- **原版/没装光影时能不能投红光？** → 不能。这是引擎层面的限制，任何模组都做不到。
